Documentation

Trace everything. Fix anything. Panduan lengkap instalasi, deployment, dan konfigurasi Trazezzo — AI-native server operations platform.

Introduction

Trazezzo adalah platform operasi server bertenaga AI yang menggabungkan tiga komponen utama:

  • Dashboard — web UI (FastAPI + Jinja2) untuk monitoring real-time, kelola services, logs, networking, storage, containers, security, dan lebih.
  • Agent Daemon — background process yang menjalankan capture sources (journald, auditd, psutil, eBPF) dan proactive loop untuk deteksi anomali.
  • AI Chatbot — asisten AI dengan dua mode: Q&A (reasoning) dan Agent (eksekusi command langsung di server).
Design Philosophy Trazezzo berjalan sebagai satu proses (bundle mode) atau terpisah (dashboard & agent terpisah pada mesin yang sama). Semua capture berbasis async I/O — tidak ada blocking operation. Agent proactive loop berjalan setiap 30 detik. Multi-server deployment (agent di VM berbeda, dashboard di VM pusat) sedang dalam pengembangan — lihat Roadmap.

Trazezzo terdiri dari layer-layer berikut:

│                                                           │

│  │  :9122      │    │              │    │              │ │

Dashboard dan Agent berbagi satu proses Python di bundle mode (default). Di separated mode, keduanya berjalan sebagai proses terpisah pada mesin yang sama dengan shared SQLite database. Agent dan dashboard harus berada di VM/server yang sama — multi-server deployment belum tersedia saat ini.

Deployment: Bundle Mode

Mode default — dashboard dan agent berjalan dalam satu proses Python via daemon_entry.py. Paling simple, paling sedikit config. Recommended untuk single-server deployment.

Bundle

Single Process

  • Dashboard + Agent di 1 proses
  • 1 systemd service
  • Shared memory, no IPC
  • Simplest deployment
Separated

Two Processes

  • Dashboard dan Agent proses terpisah
  • 2 systemd services
  • Shared SQLite database
  • Independent restart/scaling

Step-by-Step: Bundle Mode

1

Clone repository

bash
git clone https://github.com/yusufworkmail456-sys/trazezzo.git
cd trazezzo
2

Create virtualenv & install dependencies

bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
3

Install system packages

auditd untuk security event capture. bpftrace optional untuk eBPF.

bash
# Required
apt-get install -y auditd audispd-plugins
systemctl enable --now auditd

# Optional: eBPF kernel tracing
apt-get install -y bpftrace python3-bpfcc
4

Create data directory

bash
mkdir -p /var/lib/trazezzo
5

Create systemd service

Bundle mode menjalankan daemon_entry.py yang start agent + dashboard dalam satu proses.

/etc/systemd/system/trazezzo.service
[Unit]
Description=Trazezzo — AI-Native Server Operations Platform
After=network.target auditd.service

[Service]
Type=simple
ExecStart=/opt/trazezzo/.venv/bin/python -m trazezzo.daemon_entry
Restart=on-failure
RestartSec=5
Environment=TRAZEZZO_DATA_DIR=/var/lib/trazezzo
Environment=PYTHONUNBUFFERED=1
WorkingDirectory=/opt/trazezzo
User=root

[Install]
WantedBy=multi-user.target
6

Enable & start service

bash
systemctl daemon-reload
systemctl enable --now trazezzo
systemctl status trazezzo
7

Verify

bash
# Check service
systemctl is-active trazezzo

# Check API
curl http://localhost:9122/api/overview

# Check logs
journalctl -u trazezzo -f
Quick Install Trazezzo memiliki CLI yang automate steps 2-6: trazezzo init lalu trazezzo up. Lihat CLI Commands untuk detail.

Deployment: Separated Mode

Mode untuk deployment yang lebih fleksibel — dashboard dan agent berjalan sebagai proses terpisah pada mesin yang sama. Berguna ketika agent butuh resource lebih (eBPF) atau ingin restart dashboard tanpa disconnect capture. Tidak untuk multi-server — agent dan dashboard harus tetap di VM yang sama.

Step-by-Step: Separated Mode

1

Follow bundle mode steps 1-4

Clone, venv, system packages, data directory — sama seperti bundle mode.

2

Create agent-only systemd service

Agent daemon berjalan standalone via AgentDaemon.run().

/etc/systemd/system/trazezzo-agent.service
[Unit]
Description=Trazezzo Agent — Capture & Proactive Daemon
After=network.target auditd.service

[Service]
Type=simple
ExecStart=/opt/trazezzo/.venv/bin/python -c "\
from trazezzo.agent.daemon import AgentDaemon; \
import asyncio; asyncio.run(AgentDaemon().run())"
Restart=on-failure
RestartSec=5
Environment=TRAZEZZO_DATA_DIR=/var/lib/trazezzo
Environment=PYTHONUNBUFFERED=1
WorkingDirectory=/opt/trazezzo
User=root

[Install]
WantedBy=multi-user.target
3

Create dashboard-only systemd service

Dashboard berjalan standalone via uvicorn, tanpa agent daemon.

/etc/systemd/system/trazezzo-dashboard.service
[Unit]
Description=Trazezzo Dashboard — Web UI
After=network.target trazezzo-agent.service

[Service]
Type=simple
ExecStart=/opt/trazezzo/.venv/bin/uvicorn \
    trazezzo.dashboard.app:app \
    --host 127.0.0.1 \
    --port 9122
Restart=on-failure
RestartSec=5
Environment=TRAZEZZO_DATA_DIR=/var/lib/trazezzo
Environment=PYTHONUNBUFFERED=1
WorkingDirectory=/opt/trazezzo
User=root

[Install]
WantedBy=multi-user.target
4

Enable & start both services

bash
systemctl daemon-reload
systemctl enable --now trazezzo-agent
systemctl enable --now trazezzo-dashboard

# Verify both
systemctl status trazezzo-agent
systemctl status trazezzo-dashboard
Shared Database Kedua service share /var/lib/trazezzo/events.db (SQLite). Agent menulis events, dashboard membaca. SQLite handle concurrent read/write dengan WAL mode. Pastikan TRAZEZZO_DATA_DIR sama di kedua service.

Roadmap: Multi-Server Deployment

Saat ini Trazezzo beroperasi pada single VM/server — agent dan dashboard harus berada di mesin yang sama. Berikut rencana untuk multi-server deployment:

Current Limitation Agent menulis events ke SQLite lokal (/var/lib/trazezzo/events.db). Dashboard membaca dari SQLite yang sama. Tidak ada remote ingestion API atau mekanisme agent-to-dashboard antar VM. Multi-server deployment membutuhkan perubahan arsitektur.

Rencana Arsitektur Multi-Server

Tiga pendekatan yang sedang dievaluasi:

1. PostgreSQL Backend (Recommended)

Semua agent (di setiap server) dan dashboard connect ke PostgreSQL database terpusat. Agent menulis events langsung ke Postgres, dashboard membaca dari sana.

config
# /etc/trazezzo/.env
TRAZEZZO_DB_TYPE=postgresql
TRAZEZZO_DB_URL=postgresql://trazezzo:***@db.internal:5432/trazezzo

Status: Dalam pengembangan

2. Agent HTTP Forwarding

Agent di remote server mengirim events via HTTP POST ke dashboard API. Dashboard menyimpan ke SQLite lokalnya.

config
# /etc/trazezzo/.env (di agent server)
TRAZEZZO_DASHBOARD_URL=https://dashboard.internal/trazezzo
TRAZEZZO_AGENT_TOKEN=***

Status: Dalam pengembangan

Hybrid Deployment (Concept)

Untuk skenario dengan 3+ server aplikasi:

architecture
┌─────────────────────────────────────────────────────────┐
│  Server A (Dashboard + Agent)     ← Bundle mode         │
│  ├── Trazezzo Dashboard (port 9122)                      │
│  ├── Agent Daemon (local capture)                      │
│  └── SQLite/PostgreSQL (local events)                   │
│                                                         │
│  Server B (Agent only)            ← Remote agent       │
│  ├── Agent Daemon (local capture)                      │
│  └── Forward events → Server A via HTTP/DB             │
│                                                         │
│  Server C (Agent only)            ← Remote agent       │
│  ├── Agent Daemon (local capture)                      │
│  └── Forward events → Server A via HTTP/DB             │
└─────────────────────────────────────────────────────────┘
Belum Tersedia Multi-server deployment membutuhkan perubahan pada config.py (DB backend abstraction) dan sqlite_warm.py (Postgres adapter). Jika Anda ingin contribute atau track progress, cek GitHub repository.

Nginx Reverse Proxy

Nginx diperlukan untuk HTTPS termination, WebSocket support (web terminal + exec stream), dan SSE streaming (AI chatbot).

Nginx Configuration

/etc/nginx/snippets/trazezzo.conf
# Trazezzo — AI-Native Server Operations
location /trazezzo/ {
    proxy_pass http://127.0.0.1:9122/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # WebSocket support (terminal + exec stream)
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 86400;
    proxy_send_timeout 86400;

    # SSE streaming (chatbot responses)
    proxy_buffering off;
    proxy_cache off;
}

Include in server block

nginx site config
server {
    listen 443 ssl http2;
    server_name your-domain.com;

    # ... SSL config ...

    include snippets/trazezzo.conf;

    location / {
        # your default backend
    }
}
Critical Settings proxy_buffering off wajib — tanpa ini, AI chatbot streaming tidak akan bekerja. proxy_read_timeout 86400 wajib untuk WebSocket terminal agar tidak disconnect setelah 60s.

AI Agent Setup

Trazezzo AI chatbot menggunakan OpenAI-compatible API. Ada dua cara untuk mengkonfigurasi LLM backend:

Recommended

9Router

Managed LLM gateway. No API key management. Setup cepat.

  • Zero-config API key routing
  • Multi-model access via satu endpoint
  • Buka 9router.com untuk setup
Flexible

Bring Your Own Model

Gunakan provider LLM sendiri. OpenAI-compatible.

  • OpenAI, Anthropic, Ollama, vLLM, dll
  • Full kontrol model & cost
  • On-premise / self-hosted support

Option A: 9Router (Recommended)

9Router adalah managed LLM gateway yang menyediakan akses ke berbagai model melalui satu endpoint yang OpenAI-compatible. Setup akun di 9router.com, dapatkan API key, lalu konfigurasi Trazezzo:

1

Buat akun di 9router.com

Kunjungi https://9router.com untuk registrasi dan dapatkan API key Anda.

2

Store API key

Trazezzo membaca API key dari file env (bukan environment variable):

/etc/trazezzo/.env
NINEROUTER_API_KEY=sk-your-9router-api-key-here
bash
mkdir -p /etc/trazezzo
echo "NINEROUTER_API_KEY=sk-your-key-here" > /etc/trazezzo/.env
chmod 600 /etc/trazezzo/.env  # restrict access
3

Configure Trazezzo

Edit trazezzo/config.py:

config.py
# LLM Configuration — 9Router
LLM_BASE_URL     = "https://9router.com/v1"
LLM_MODEL        = "coding"
LLM_ENV_KEY_NAME = "NINEROUTER_API_KEY"
LLM_ENV_PATH     = "/etc/trazezzo/.env"
4

Restart & verify

bash
systemctl restart trazezzo
# Test AI chatbot dari dashboard

Trazezzo kompatibel dengan provider apapun yang mendukung OpenAI chat completions API. Termasuk OpenAI, Anthropic (via compatibility layer), Ollama, vLLM, LM Studio, dan lainnya.

Edit trazezzo/config.py sesuai provider Anda.

Chat Modes

AI Chatbot memiliki dua mode operasi yang bisa di-toggle dari UI:

ModeBehaviorUse Case
Q&A (Reasoning) Streaming text response. Read-only. LLM menerima konteks server dan menjawab pertanyaan. "Server lemot, kenapa?"
Agent Full operation mode. LLM dapat propose commands (exec, read_file, write_file, git_push, service_action) yang dieksekusi di server. "Restart nginx dan cek config"

Agent mode menggunakan structured JSON action blocks yang diparse dari LLM output:

Action format
# LLM outputs inline JSON action blocks:
{
  "tool": "exec",
  "command": "systemctl status nginx"
}

# Available tools:
# exec           — run shell command (with safety checks)
# read_file      — read file contents
# write_file     — write content to file
# list_dir       — list directory contents
# git_push       — git add + commit + push
# service_action — start/stop/restart a service

Proactive Modes

Proactive agent berjalan di background dengan interval 30 detik. Mendeteksi anomali dan merespon berdasarkan mode yang dipilih.

Default

Calm Mode

Advisory only. AI mengawasi dan menyarankan.

  • Monitoring 24/7 semua metrik
  • Deteksi: CPU spike, disk full, OOM, failed services
  • Rekomendasi muncul di dashboard & chat
  • Timeline event dengan atribusi aktor
  • Tidak ada eksekusi tanpa approval manual
Pro

Aggressive Mode

Auto-remediation dengan allowlist keamanan.

  • Semua fitur Calm Mode
  • Auto-restart failed services
  • Auto-kill OOM processes
  • Auto-cleanup journal & apt cache
  • Renice CPU hog processes
  • Approval queue untuk action di luar allowlist

Switching Modes

Mode bisa di-toggle dari dashboard (chat panel → Calm/Aggressive toggle) atau via API:

bash
# Check current mode
curl http://localhost:9122/api/proactive/status

# Switch to aggressive
curl -X POST http://localhost:9122/api/proactive/mode \
  -H "Content-Type: application/json" \
  -d '{"mode":"aggressive"}'

# Switch back to calm
curl -X POST http://localhost:9122/api/proactive/mode \
  -H "Content-Type: application/json" \
  -d '{"mode":"calm"}'
Aggressive Mode Safety Saat mengaktifkan aggressive mode, confirmation dialog muncul di UI. Semua auto-executed actions harus ada di allowlist. Action di luar allowlist masuk ke approval queue — user harus approve sebelum eksekusi.

Allowlist & Safety

Allowlist mendefinisikan action apa saja yang boleh di-auto-execute di aggressive mode. Didefinisikan di scheduler.py:

scheduler.py
AGGRESSIVE_ALLOWLIST = {
    "service.restart":     "systemctl restart {unit}",
    "service.start":       "systemctl start {unit}",
    "process.kill_oom":    "kill -9 {pid}",
    "disk.cleanup_journal": "journalctl --vacuum-time=2d",
    "disk.cleanup_apt":     "apt-get clean",
    "process.nice":        "renice +10 {pid}",
}

Approval Flow

Untuk action yang tidak ada di allowlist, proactive agent menyimpannya sebagai pending approval:

Approval flow
1. Agent detects anomaly (e.g., disk 98% full)
2. Agent proposes action not in allowlist
3. store_pending_approval() saves to /var/lib/trazezzo/pending_approvals.json
4. Approval appears in chat panel with command + reason
5. User clicks "Approve & Execute" or "Reject"
6. If approved: command executed, result shown in chat
7. If rejected: approval removed

Pending Approvals API

bash
# List pending approvals
curl http://localhost:9122/api/approvals

# Approve
curl -X POST http://localhost:9122/api/approvals/{id}/approve

# Reject
curl -X POST http://localhost:9122/api/approvals/{id}/reject

Event Attribution

Setiap event di warm store diklasifikasi berdasarkan aktor:

Actor KindSumberContoh Event
user Login session (UID >= 1000 atau sudo) auth.login, auth.sudo, session.open, file.config_change
agent Trazezzo sendiri (proactive action, recommendation execute, dashboard action, chatbot agent mode) agent.action, agent.advisory, service.restart
system Kernel, systemd, daemon service.fail, process.oom, metric.spike, net.connect
Warm Store Architecture SQLite WAL mode, 7 hari retention, in-memory ring buffer (5 menik hot window), batched insert (500 event/insert). Semua capture source menulis async ke store yang sama, dashboard baca.. Tdk, attribute (user/agent/system) memungkinkan query: "berapa event agent minggu ini?" atau "apa yang user lakukan 5 menit sebelum crash?"

Bagaimana Trazezzo memudahkan operational, monitoring, dan maintenance dibanding fully CLI-based server management? Berikut perbandingan detail per aspek.

Auto-Remediation Tidak ada. Admin harus manual restart setiap service yang gagal. Aggressive mode: auto-restart failed services, auto-kill OOM, auto-cleanup disk, renice CPU hog. Allowlist keamanan. Approval queue untuk action di luar allowlist.

Knowledge Retention Sysadmin hafal di kepala. Junior harus belajar dari awal. Tidak ada konteksual AI. AI chatbot dengan real-time system context. "Kenapa nginx down?" → AI cek service, log, config, berikan jawaban dengan data. Timeline untuk post-mortem analysis.
Ringkasan CLI-based: setiap task = command terpisah, hafal manual, tanpa konteksual antar-komponen. Trazezzo: AI unifikasi operasi, monitoring, dan maintenance dalam satu dashboard — dengan event attribution, causal timeline, dan proactive auto-remediation.
