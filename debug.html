Debug & Troubleshooting

Panduan troubleshooting untuk error umum saat instalasi, deployment, dan operasional Trazezzo. Quick diagnose, common fixes, step-by-step.

Quick Health Check

Sebelum debugging mendalam, jalankan health check untuk tahu status Trazezzo secara cepat.

bash 
# 1. Check service status
systemctl is-active trazezzo

# 2. Check API responds
curl -s http://localhost:9122/api/overview | python3 -m json.tool

# 3. Check database exists
ls -lh /var/lib/trazezzo/events.db

# 4. Check port listening
ss -tlnp | grep 9122

# 5. Check nginx proxy
curl -s http://localhost/trazezzo/api/overview

# 6. Check LLM connectivity
curl -s https://9router.amital.co.id/v1/models -H "Authorization: Bearer $HERMES_CUSTOM_9ROUTER_AMITAL_CO_ID_API_KEY"

# 7. Check disk space
df -h /var/lib/trazezzo/
One-liner: trazezzo status Jalankan trazezzo status untuk summary cepat: service status, hostname, uptime, CPU/RAM, DB size.

Log Check

Trazezzo logs ke journald. Filter berdasarkan severity untuk cepat menemukan error.

bash 
# All logs (follow)
journalctl -u trazezzo -f

# Errors only (last 100)
journalctl -u trazezzo -p err --no-pager -n 100

# Last 50 lines
journalctl -u trazezzo --no-pager -n 50

# Since boot
journalctl -u trazezzo -b

# Specific time range
journalctl -u trazezzo --since "2024-01-01 00:00:00" --until "2024-01-01 12:00:00"

# Grep for specific error
journalctl -u trazezzo --no-pager | grep -i "error"

Common Log Patterns

Address already in use ERROR Port Conflict
database is locked ERROR SQLite Locked
Permission denied ERROR Permission Denied

Agent daemon started INFO Normal startup
Proactive check error ERROR Service Issues

Python Version Error

Error ERROR: Package 'trazezzo' requires a different Python: 3.10.12 not in '>=3.12'

Trazezzo membutuhkan Python 3.12 atau lebih baru (untuk type hint syntax, match/case, dan performance improvements).

Diagnose

bash
python3 --version

Fix: Install Python 3.12 (Ubuntu 22.04)

bash
# Add deadsnakes PPA
apt-get update
apt-get install -y software-properties-common
add-apt-repository -y ppa:deadsnakes/ppa
apt-get update

# Install Python 3.12
apt-get install -y python3.12 python3.12-venv python3.12-dev

# Verify
python3.12 --version

# Recreate venv with 3.12
cd /opt/trazezzo
rm -rf .venv
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e .

Fix: Ubuntu 24.04+ (Python 3.12 sudah default)

bash
python3 --version  # should be 3.12+

# If somehow still old, update python3 symlink
update-alternatives --install /usr/bin/python3 python3 /usr/bin/python3.12 1

pip install Failure

Error error: command 'gcc' failed with exit status 1 atau fatal error: Python.h: No such file or directory

Beberapa dependency (psutil, pydantic) butuh compile dari source. Install build tools.

Fix

bash
# Install build dependencies
apt-get install -y build-essential python3.12-dev

# Retry
pip install -e .

Alternative: Use pre-built wheels

bash
# Force binary wheels only (no source build)
pip install -e . --only-binary :all:

# If that fails, allow fallback
pip install -e . --prefer-binary
psutil compile error on ARM? psutil mungkin gagal compile di ARM (Raspberry Pi, Graviton). Install apt-get install -y python3.12-dev gcc dan retry. Jika masih gagal, coba pip install psutil==6.0.0 (versi yang punya pre-built wheel untuk ARM).

Virtualenv Issues

Error bash: .venv/bin/activate: No such file or directory atau bash: trazezzo: command not found

Venv belum dibuat atau rusak. Recreate.

Fix

bash
# Delete old venv
rm -rf /opt/trazezzo/.venv

# Recreate
cd /opt/trazezzo
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e .

# Re-init (writes systemd service with correct venv path)
python -m trazezzo.main init

# Restart service
systemctl daemon-reload
systemctl restart trazezzo

Check venv python path in systemd

Pastikan ExecStart di systemd service menunjuk ke venv python yang benar:

bash
# Check
grep ExecStart /etc/systemd/system/trazezzo.service

# Should be:
# ExecStart=/opt/trazezzo/.venv/bin/python -m trazezzo.daemon_entry

# If wrong, fix manually or re-run init
python -m trazezzo.main init

auditd Not Found

Error FileNotFoundError: [Errno 2] No such file or directory: '/var/log/audit/audit.log'

auditd belum terinstall atau belum dienable. Trazezzo butuh auditd untuk security event capture (execve, login, file events).

Fix

bash
# Install auditd
apt-get install -y auditd audispd-plugins

# Enable & start
systemctl enable --now auditd

# Verify
systemctl is-active auditd
ls -la /var/log/audit/audit.log

# Test: generate audit event
cat /etc/passwd > /dev/null

# Check audit log captured it
tail -5 /var/log/audit/audit.log
Trazezzo tetap berjalan tanpa auditd Jika auditd tidak bisa diinstall (container, restricted env), Trazezzo tetap berfungsi — hanya tanpa kernel audit event capture. journald + psutil tetap aktif.

eBPF / bpftrace Not Available

Warning (bukan error) eBPF capture not available: No module named 'bcc'

eBPF capture optional. Trazezzo tetap berfungsi penuh tanpa eBPF. Jika ingin kernel syscall tracing:

Requirements

  • Kernel >= 5.8
  • bpftrace terinstall
  • python3-bpfcc (Python binding untuk BPF Compiler Collection)
  • Root access (CAP_BPF capability)

Fix

bash
# Check kernel version
uname -r  # should be >= 5.8

# Install bpftrace + bcc
apt-get install -y bpftrace python3-bpfcc

# Verify bpftrace works
bpftrace --version

# Restart Trazezzo
systemctl restart trazezzo

# Check log — should NOT show "eBPF capture not available"
journalctl -u trazezzo --no-pager -n 20 | grep -i ebpf
Container / VM limitations eBPF tidak akan berfungsi di container tanpa --privileged atau CAP_BPF. Pada VM, pastikan kernel host mendukung BPF (bukan hanya kernel container). Jika tidak memungkinkan, abaikan — Trazezzo tetap punya journald + auditd + psutil.

Diagnose

bash

    proxy_pass http://127.0.0.1:9123/;  # match new port

Permission Denied

Error PermissionError: [Errno 13] Permission denied: '/var/lib/trazezzo/events.db'

Trazezzo butuh root untuk auditd, eBPF, service management, dan file access. Systemd service harus run as User=root.

Fix

bash
# Check service user
grep "^User=" /etc/systemd/system/trazezzo.service
# Should be: User=root

# Fix data directory ownership
chown -R root:root /var/lib/trazezzo/
chmod 755 /var/lib/trazezzo/

# If running as non-root user, change to root
sed -i 's/^User=.*/User=root/' /etc/systemd/system/trazezzo.service
systemctl daemon-reload
systemctl restart trazezzo
Do NOT run Trazezzo as non-root Tanpa root: auditd capture gagal, eBPF gagal, systemctl action gagal, journalctl restricted. Trazezzo didesain untuk run as root di server operasional.

Dashboard Unreachable

Service running tapi dashboard tidak bisa diakses. Step-by-step diagnose.

Step 1: Check service is active

bash
systemctl is-active trazezzo  # should print "active"

Step 2: Check local API

bash
# Direct to uvicorn
curl -v http://127.0.0.1:9122/api/overview

# If connection refused → uvicorn not running (check logs)
# If 200 OK → local works, problem is nginx

Step 3: Check nginx

bash
# Test nginx config
nginx -t

# Check trazezzo location is included
grep -r trazezzo /etc/nginx/

# Reload nginx
systemctl reload nginx

# Test via nginx
curl -v http://localhost/trazezzo/api/overview

Step 4: Check HTTPS / external

bash
# Test public URL
curl -v https://your-domain/trazezzo/api/overview

# If SSL error → check cert
openssl s_client -connect your-domain:443 -servername your-domain </dev/null 2>/dev/null | openssl x509 -noout -dates

# If timeout → check firewall
ufw status
iptables -L -n | grep -E "80|443"

502 Bad Gateway

Error Browser menampilkan 502 Bad Gateway saat mengakses /trazezzo/

Nginx tidak bisa connect ke uvicorn (port 9122). Penyebab umum:

CauseCheckFix
Trazezzo service down systemctl is-active trazezzo systemctl start trazezzo
Uvicorn bind 127.0.0.1 only ss -tlnp | grep 9122 Should be 127.0.0.1:9122 (nginx proxy handles external)
Wrong proxy_pass in nginx grep proxy_pass /etc/nginx/snippets/trazezzo.conf Must be http://127.0.0.1:9122/
Uvicorn crashed journalctl -u trazezzo -p err -n 20 Fix error, systemctl restart trazezzo
Quick check systemctl is-active trazezzo && curl -s http://127.0.0.1:9122/api/overview | head -1 — jika keduanya OK, problem ada di nginx config. Reload: systemctl reload nginx.

WebSocket Connection Failed

Error Browser console: WebSocket connection to 'wss://...' failed. Web terminal dan execution panel tidak berfungsi.

Nginx butuh WebSocket upgrade config. Pastikan snippet trazezzo.conf memiliki:

nginx
location /trazezzo/ {
    proxy_pass http://127.0.0.1:9122/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # ── WebSocket support (REQUIRED) ──
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 86400;
    proxy_send_timeout 86400;

    # ── SSE / streaming support ──
    proxy_buffering off;
    proxy_cache off;
}

Fix

bash
# Re-write nginx snippet (or run trazezzo init)
python -m trazezzo.main init

# Test & reload
nginx -t && systemctl reload nginx

SSE / Chat Not Streaming

Error Chat response muncul sekaligus di akhir (bukan streaming per-kata). Atau chat timeout setelah 60 detik.

Nginx buffering response. SSE (Server-Sent Events) butuh proxy_buffering off.

Fix

nginx
# Add these to trazezzo nginx location block:
proxy_buffering off;
proxy_cache off;
proxy_read_timeout 120s;  # LLM response can take time
bash
nginx -t && systemctl reload nginx
Direct (no nginx) works fine? Jika curl http://127.0.0.1:9122/api/chat streaming dengan benar tapi via nginx tidak, pasti nginx buffering. Check: grep proxy_buffering /etc/nginx/snippets/trazezzo.conf harus return off.

SQLite Database Locked

Error sqlite3.OperationalError: database is locked

SQLite WAL mode biasanya handle concurrent read/write. Tapi jika terjadi lock:

Fix

bash
# Check for stale lock files
ls -la /var/lib/trazezzo/events.db*

# Check WAL mode
sqlite3 /var/lib/trazezzo/events.db "PRAGMA journal_mode;"
# Should return: wal

# If stuck, checkpoint WAL
sqlite3 /var/lib/trazezzo/events.db "PRAGMA wal_checkpoint(TRUNCATE);"

# If still locked, restart service (releases all connections)
systemctl restart trazezzo

# Nuclear option: delete WAL/SHM files (service must be stopped)
systemctl stop trazezzo
rm /var/lib/trazezzo/events.db-wal /var/lib/trazezzo/events.db-shm
systemctl start trazezzo
Recurring lock? Check for separated mode Jika menggunakan separated mode (agent + dashboard proses terpisah), pastikan keduanya menggunakan TRAZEZZO_DATA_DIR yang sama. SQLite WAL mendukung multi-process, tapi path harus identik.

Database Corrupt

Error sqlite3.DatabaseError: database disk image is malformed

Fix: Recover what you can, recreate

bash
systemctl stop trazezzo

# Try to recover data
sqlite3 /var/lib/trazezzo/events.db .dump > /tmp/trazezzo_dump.sql 2>/dev/null

# Backup corrupt db
mv /var/lib/trazezzo/events.db /var/lib/trazezzo/events.db.corrupt.$(date +%s)

# Recreate from dump (if dump has data)
sqlite3 /var/lib/trazezzo/events.db < /tmp/trazezzo_dump.sql

# Or just start fresh (lose event history)
rm /var/lib/trazezzo/events.db*

systemctl start trazezzo
Losing event history is OK Trazezzo event store adalah warm cache (7 hari retention). Kehilangan data tidak menghentikan operasi. Services, configs, dan system state tidak disimpan di SQLite — hanya event history untuk timeline dan activity feed.

Disk Full

Error OSError: [Errno 28] No space left on device atau service crash berulang.

Diagnose

bash
# Check disk
df -h

# Check Trazezzo DB size
ls -lh /var/lib/trazezzo/

# Check journal size
journalctl --disk-usage

Fix

bash
# 1. Vacuum journal (biggest win usually)
journalctl --vacuum-time=2d
journalctl --vacuum-size=100M

# 2. Clean apt cache
apt-get clean

# 3. Archive old Trazezzo events (manual sync)
cd /opt/trazezzo
source .venv/bin/activate
python -c "from trazezzo.modules.sync import archive_warm_to_cold; print(archive_warm_to_cold())"

# 4. If DB itself is huge, prune old events manually
sqlite3 /var/lib/trazezzo/events.db "DELETE FROM events WHERE ts < datetime('now', '-3 days');"
sqlite3 /var/lib/trazezzo/events.db "VACUUM;"

# 5. Restart
systemctl restart trazezzo
Enable aggressive mode for auto-cleanup POST /api/proactive/mode {"mode":"aggressive"} — Trazezzo akan auto-cleanup journal + apt cache saat disk >95%.

LLM API Key Invalid

Error Cannot read API key from /root/.hermes/.env: ... atau 401 Unauthorized dari 9router.

Trazezzo membaca API key dari file env Hermes. Key name: HERMES_CUSTOM_9ROUTER_AMITAL_CO_ID_API_KEY.

Diagnose

bash
# Check env file exists
ls -la /root/.hermes/.env

# Check key is present (don't print value)
grep -c "HERMES_CUSTOM_9ROUTER_AMITAL_CO_ID_API_KEY" /root/.hermes/.env
# Should print: 1

# Check config.py points to right file
grep -E "LLM_ENV_KEY_NAME|LLM_ENV_PATH" /opt/trazezzo/trazezzo/config.py

Fix

bash
# Add key to Hermes env file (if missing)
echo "HERMES_CUSTOM_9ROUTER_AMITAL_CO_ID_API_KEY=your-key-here" >> /root/.hermes/.env

# If key exists but wrong → get correct key from 9router dashboard

# Restart Trazezzo to pick up new key
systemctl restart trazezzo

# Test chat
curl -X POST http://localhost:9122/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"halo","mode":"reasoning"}'
Using different LLM provider? Edit config.py: LLM_BASE_URL, LLM_MODEL, LLM_ENV_KEY_NAME, LLM_ENV_PATH. Any OpenAI-compatible API works (Ollama, vLLM, LM Studio, OpenAI direct).

LLM Timeout

Error httpx.ReadTimeout atau chat response terputus setelah 60 detik.

Default timeout 60s (non-streaming) / 120s (streaming). LLM yang lambat atau model besar bisa timeout.

Fix: Increase timeout in llm.py

llm.py
# chat_completion: increase timeout
async with httpx.AsyncClient(timeout=120.0) as client:  # was 60.0

# chat_completion_stream: increase timeout
async with httpx.AsyncClient(timeout=300.0) as client:  # was 120.0
bash
systemctl restart trazezzo

Agent Mode Stuck

Error Agent mode tidak menyelesaikan task. Chat spinning tanpa hasil. Atau agent berulang eksekusi command yang sama.

Agent mode memiliki max 8 round. Jika LLM terus propose action tanpa konklusi, akan berhenti setelah 8 round dengan "Max execution rounds reached."

Common Causes

  • LLM tidak membaca execution result dengan baik → tambahkan instruksi lebih spesifik di prompt
  • Command yang dieksekusi gagal berulang → LLM tidak tahu cara alternatif
  • Command timeout (default 60s) → LLM tidak dapat result

Fix

chat_agent.py
# Increase max rounds
max_rounds = 12  # was 8

# Increase command timeout
MAX_EXEC_TIMEOUT = 120  # was 60

# Increase max output per command
MAX_OUTPUT = 8000  # was 4000
bash
systemctl restart trazezzo
Agent stuck di command yang sama? Clear chat history (tombol 🗑 di chat panel) lalu coba lagi dengan instruksi lebih spesifik. Contoh: bukan "fix nginx" tapi "baca /etc/nginx/nginx.conf, cari syntax error, fix, restart nginx".

Journald Capture Empty

Error Activity feed / timeline kosong. Tidak ada event dari journald source.

Diagnose

bash
# Check journald works
journalctl --no-pager -n 5

# Check Trazezzo capture log
journalctl -u trazezzo --no-pager | grep -i journald

psutil Shows Wrong Metrics

Error CPU menampilkan 0% atau 100% terus. Memory tidak sesuai. Disk usage salah.

Cause: psutil first call returns 0.0 for CPU

psutil.cpu_percent() return 0.0 pada first call (tidak ada baseline). Trazezzo menggunakan interval=0.5 yang seharusnya mengatasi ini, tapi bisa gagal pada system yang sangat cepat.

Fix: Warm up psutil

system.py
# Add warmup call before actual measurement
psutil.cpu_percent(interval=None)  # non-blocking warmup
import time
time.sleep(0.1)
cpu_percent = psutil.cpu_percent(interval=0.5)  # now accurate

Cause: Container metrics

Di container (Docker/Podman), psutil menampilkan metrics host, bukan container. Gunakan /proc filesystem atau cgroup metrics untuk akurasi.

trazezzo update Fail

Error git pull failed: error: Your local changes to the following files would be overwritten by merge

Fix

bash
cd /opt/trazezzo

# Option 1: Stash local changes, pull, restore
git stash
git pull origin main
git stash pop
pip install -e .
systemctl restart trazezzo

# Option 2: Discard local changes (lose modifications!)
git checkout .
git pull origin main
pip install -e .
systemctl restart trazezzo

# Option 3: If merge conflicts on stash pop
git mergetool  # resolve manually
pip install -e .
systemctl restart trazezzo
Not a git repository? Jika trazezzo update gagal dengan "Not a git repository", Trazezzo diinstall tanpa git clone. Fix: cd /opt/trazezzo && git init && git remote add origin https://github.com/yusufworkmail456-sys/trazezzo.git && git fetch && git checkout main.

GitHub Token Invalid

Error GitHub page menampilkan "Invalid or expired token". Atau agent git_push tool gagal.

Fix: Re-save token

  1. Buat new Personal Access Token (PAT) di GitHub → Settings → Developer settings → Personal access tokens
  2. Buka Trazezzo dashboard → /trazezzo/github
  3. Klik "Reset Token", paste new PAT, save

Atau via API:

bash
# Delete old token
rm /var/lib/trazezzo/github_token.json

# Save new token via Python
source /opt/trazezzo/.venv/bin/activate
python -c "from trazezzo.modules.github import save_token; print(save_token('ghp_your_new_token_here'))"

Required PAT scopes

  • repo — full control of private repos (for push + PR)
  • read:org — if accessing org repos

SSL Certificate Expired

Error Browser: NET::ERR_CERT_DATE_INVALID. Dashboard tidak bisa diakses via HTTPS.

Diagnose

bash
# Check cert expiry
openssl s_client -connect your-domain:443 -servername your-domain </dev/null 2>/dev/null \
  | openssl x509 -noout -dates

# Or use Trazezzo's built-in scanner
curl -s http://localhost:9122/api/security | python3 -m json.tool | grep -A2 "days_left"

Fix: Renew Let's Encrypt

bash
# Renew with certbot
certbot renew

# Reload nginx to pick up new cert
systemctl reload nginx

# Verify
openssl s_client -connect your-domain:443 -servername your-domain </dev/null 2>/dev/null \
  | openssl x509 -noout -dates
Auto-renewal Setup cron: 0 3 * * * certbot renew --quiet && systemctl reload nginx — renew check setiap hari jam 3 pagi. Trazezzo SSL scanner juga mengingatkan saat cert akan expired dalam 30 hari.
